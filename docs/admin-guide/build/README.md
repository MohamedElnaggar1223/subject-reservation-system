# Regenerating the admin guide

`../index.html` and `../img/` are written by `gen.py` from three inputs: `steps.py` (every step's words), `guide-data.json` (the June 2027 session as the 25 forms describe it: subjects, teachers, papers, awards, option codes, the sheet's values, the fee lists, the dates — the same file the drive types into the screens) and the drive's screenshots. To change the words only, edit `steps.py` and run `python3 gen.py`: a screenshot missing from `SHOTS` (default `/tmp/ag/shots`) is kept from `../img/`. Then check the page offline with `node check-page.mjs` (every image loads, every link inside the page resolves, no request leaves the file).

When the screens change, take the screenshots again: run the app locally on an empty database (as in `docs/walkthrough/index.html` Part 1, with the web on port 3230 and the API on 3231, or set `BASE`, `API`, `WT` and `DB`), `npm install` in this folder (it gives the drive and the check `playwright-core`; they use the installed Chrome), then `drive/run-all.sh`. It recreates the database, migrates it, signs up and promotes the admin, and drives every chapter through the screens in the guide's order (`d1-start.mjs` … `d8-preview-open.mjs`), writing each JPEG (1280×900, under 150 KB) to `SHOTS` under the names `steps.py` uses; then run `gen.py` and `check-page.mjs`. Never run the drive against the deployed system: it builds a practice copy of the session.
